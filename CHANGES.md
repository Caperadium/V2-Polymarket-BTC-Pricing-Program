- Fix settlement stuck-UNSETTLEABLE bug + make data_fetcher CSV writes atomic. Diagnosed live on the VPS 2026-07-11: the whole expiring ladder stayed UNSETTLEABLE for hours after the 12:00 ET instant because `settlement_handler.BTCDataProvider` lazy-loaded `DATA/btc_intraday_1m.csv`/`btc_daily.csv` once and cached them for the life of the process -- the first settle attempt (seconds after the instant, before the 30-min datafetch timer wrote a bar covering it) froze a stale view, so the 24h retry window could never succeed (near-deterministic every expiry; downstream symptoms: all quotes PULLED on LIQ_DEGENERATE, snapshot_failed every tick, self-heal only via the 26h settlement_timeout exit). Fix: `BTCDataProvider.refresh()` mtime-invalidates path-backed frames, called once at the top of `_resolve_settlement_spot` (frames stay pinned within one resolution; `_ensure_loaded` unchanged); injected test frames are static; a torn-read guard keeps a non-empty cache when a reload parses empty (and does not advance the stored mtime, so the next refresh retries). Separately, a one-off engine CRITICAL ("intraday data is 9140 hours stale") came from reading the ~105MB intraday CSV mid-rewrite: `data_fetcher.py` now writes all three CSVs via `_write_csv_atomic` (same-dir tmp + `os.replace`), so readers see old-complete or new-complete, never truncated; all mtime consumers (staleness guard, R1 re-read, alert check, datafetch skip logic) unaffected. Tests: masking test renamed `test_retry_settles_when_provider_replaced`, 4 new settlement-provider tests (path-backed retry, torn-read guard, empty-then-populated, injected-static), new `tests/test_data_fetcher_atomic_write.py`; 436 mm tests pass. Files: market_maker/settlement_handler.py, core/data/data_fetcher.py, tests/test_mm_settlement_handler.py, tests/test_data_fetcher_atomic_write.py, CLAUDE.md, DOCS/concepts/market-making.md.

- Fix MM pricer jump-parameter wiring + re-anchor engine jump defaults. Diagnostic experiments (posterior credible bands, then a three-way defaults/bipower/posterior comparison -- see temp/VR.md sections 7-8) show the bipower calibration matches the conjugate posterior on every Kou parameter, but the hardcoded engine defaults (CRASH_PROB=0.6, ETA_UP=50, ETA_DOWN=25; implied jump drift -40%/yr vs -10%/yr calibrated) inflate ATM P(S_T >= K) by ~1.2-1.5 cents at 1-7 DTE. The market-maker's CachedEngine (market_maker/shadow_runner.py) passed no jump_params and therefore priced on those defaults -- the MM fair-value ladder ran ~1.2-1.5c rich near ATM. Fix A: CachedEngine now loads bipower-calibrated jumps via load_calibrated_jumps on the GARCH-refit cadence (run_full_pipeline's lam->lambda key mapping; falls back to engine defaults with a warning if calibration is unavailable/unconverged). Fix B: module defaults re-anchored to the calibration (CRASH_PROB 0.54, ETA_UP 35.0, ETA_DOWN 32.0) so unwired callers degrade gracefully. Updated CLAUDE.md (FIX 2/M1 bullet, shadow_runner line) and DOCS/concepts/pricing-engine.md (defaults table). Files: market_maker/shadow_runner.py, core/pricing/btc_pricing_engine.py, CLAUDE.md, DOCS/concepts/pricing-engine.md.
